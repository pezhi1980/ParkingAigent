# DK Parking Engine — iOS Phase 9 Vertical Slice Setup Guide

## Prerequisites

- macOS 13+ with Xcode 15+
- Physical iPhone (iOS 16+) with ARKit support
- Apple Developer account (for device provisioning)

---

## Project structure

```
ios/
  DKParkingSDK/               ← Swift Package (SDK framework)
    Package.swift
    Sources/DKParkingSDK/
      Core/                   ← DecisionState, RefusalReasonCode, ParkingEvaluationResult,
      │                         PolicyRegistry, LegalThresholds
      AR/                     ← ARMeasurementSession
      Evaluation/             ← ConfidenceComposer, LegalEvaluator
      Engine/                 ← ParkingEvaluationEngine (main entry point)
    Tests/DKParkingSDKTests/  ← ConfidenceComposerTests, LegalEvaluatorTests,
                                MeasurementBundleTests

  DKParkingVerticalSlice/     ← iOS App (vertical slice)
    DKParkingVerticalSliceApp.swift
    VerticalSliceRootView.swift
    Info.plist
```

---

## Step 1: Open the SDK package in Xcode (run unit tests)

1. Open Xcode → **Open a project or file** → select `ios/DKParkingSDK/Package.swift`.
2. In the scheme picker, select an **iOS simulator** destination (e.g. iPhone 16).
   > The SDK imports `ARKit` which is iOS-only. Tests must target an iOS simulator, not "My Mac".
3. Run tests with **Cmd+U**.
4. All tests in `ConfidenceComposerTests`, `LegalEvaluatorTests`, and `MeasurementBundleTests` should pass.
   > `ARMeasurementSession` itself is not unit-tested here (requires a real ARKit session on device).
   > The tested logic (ConfidenceComposer, LegalEvaluator, MeasurementBundle, thresholds) is pure Swift.

---

## Step 2: Create the vertical slice Xcode project

1. In Xcode → **File → New → Project → iOS → App**.
2. Product name: `DKParkingVerticalSlice`
3. Bundle ID: `dk.parking.verticalslice`
4. Interface: **SwiftUI**, Language: **Swift**, minimum deployment: **iOS 16**
5. Save the project into `ios/DKParkingVerticalSlice/`.
6. **Delete** the template `ContentView.swift` and `<AppName>App.swift` generated by Xcode.
7. **Add** the two source files from this repo:
   - `DKParkingVerticalSliceApp.swift`
   - `VerticalSliceRootView.swift`
8. Copy `Info.plist` from this folder into the Xcode project (or merge the keys into the existing generated Info.plist).

---

## Step 3: Add DKParkingSDK as a local Swift Package dependency

1. In Xcode → Project navigator → select the project root → **Package Dependencies** tab.
2. Click **+** → **Add Local…** → select `ios/DKParkingSDK/`.
3. Xcode will resolve the package; add `DKParkingSDK` to the app target's **Frameworks, Libraries, and Embedded Content**.

---

## Step 4: Configure signing and capabilities

1. Select the app target → **Signing & Capabilities**.
2. Set **Team** to your developer team.
3. Enable **ARKit** in the capability list (adds `NSCameraUsageDescription` to the build if not already present).
4. Connect a physical device and select it as the build destination.

---

## Step 5: Build and run

1. **Cmd+R** to build and run on the physical device.
2. Accept the camera permission prompt.
3. Point the phone at a flat surface (ground, floor).
4. Wait for the status banner to turn **green** (AR session valid).
5. Tap **Evaluate** to run the `pedestrian_crossing_5m` synthetic geometry evaluation.
6. Observe the result card displaying decision state, measurement values, confidence, and disclosure.

---

## Step 6: Fill in vertical_slice_report.md

After running on device, open `vertical_slice_report.md` (in the repo root) and complete:
- Section 3 — physical device run checklist (tick each item)
- Section 4 — any strategy document adjustments needed
- Section 5 — actual test scenario results
- Section 6 — verdict

---

## Notes

- The vertical slice uses **synthetic geometry** (hardcoded vehicle edge and boundary points).
  Full real-world geometry (ML detection + dataset feature lookup) is Phase 10+ work.
- The SDK's `evaluate()` call is synchronous and must be called from the main thread
  (the ViewModel ensures this via `@MainActor`).
- `LegalThresholds` values (5m, 10m, 12m) are non-configurable per `LEGAL_THRESHOLDS.md`.
  Do not modify them without a MAJOR SDK version bump and legal-source review.
